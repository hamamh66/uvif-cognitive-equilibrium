\section{A Concrete Research Agenda}
\label{sec:future}

\subsection{Start with an instrumented cognitive task}
A practical first test is a sequential information-sampling task with an explicit processing budget and a resource reserve carried between episodes. The agent chooses whether to gather more information or act; both choices have recorded costs and consequences. The environment should expose ground-truth transitions for verification while controlling what each agent can observe. This setting connects the cognitive allocation question to measurable system dynamics without requiring claims across every proposed domain.

Before fitting, specify the state variables, observation and transition models, component functions, normalization constants, constraints, reserve dynamics, and weight-update rules. Separate task benefit from the definition of equilibrium. Record how parameters are chosen and which information is available during training and evaluation. This specification should make it possible to reproduce each policy decision.

\subsection{Compare matched models on held-out conditions}
Include a fixed-weight model as a diagnostic baseline, but also compare against adaptive constrained optimization or control, resource-rational allocation with carry-over, and a resource-aware active-inference model where feasible. Give the models the same observations, action set, reserve dynamics, and operational constraints. Report parameter counts, tuning budgets, training cost, and online cost.

Use disjoint calibration and evaluation conditions, varying resource scarcity, observation quality, deployment duration, and disturbance severity. Fix model selection rules before inspecting evaluation outcomes. For stochastic experiments, report independent runs, uncertainty intervals, effect sizes, and the procedure used to choose the number of runs. Human studies require a separate design with appropriate ethical review and a justified sample-size plan.

\subsection{Define meaningful outcomes and negative evidence}
Primary outcomes should include retained task performance, resource depletion, violation frequency, and recovery after controlled perturbations. Reserve thresholds and unacceptable events must be determined independently of the UVIF score. Measure component computation and monitoring overhead. Report all predefined outcomes, including cases in which a baseline performs better.

For H1--H4, specify the predicted direction and the circumstances under which no effect is expected. Compare both frozen and retuned ablations so that loss of calibration is not mistaken for evidence of a necessary component. A model whose additional fields do not improve held-out prediction, operational trade-offs, or diagnostic usefulness over a simpler matched model would not justify its extra complexity in that setting.

\subsection{Establish stability and reproducibility before expansion}
A subsequent theoretical programme should address invariant sets, control feasibility, disturbance bounds, and tracking in the chosen implementation. A useful result would state assumptions under which a particular controller maintains specified constraints for a specified class of disturbances. It would not imply universal safety or unrestricted persistence.

Release a versioned implementation, environment definitions, calibration and evaluation splits, parameter settings, random seeds, software dependencies, and scripts that regenerate all reported tables and plots. A permanent archive identifier or immutable commit is preferable to a moving repository alone. Only after this focused evaluation should the framework be extended to additional domains or multi-agent systems, where individual persistence and collective welfare may conflict.
